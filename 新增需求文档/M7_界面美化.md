## 一、功能描述

统一视觉风格，提升观感。**按 Friday 指示可后置**（原话："反正是 CSS，晚点做美化也来得及"）。

---

## 二、现状（代码勘探结论）

| 问题 | 现状 |
|---|---|
| **无 UI 组件库** | 依赖里只有 axios / pinia / vue / vue-router，**没有 Element Plus 等** |
| **无全局样式** | **没有任何 CSS 文件**，全局样式只在 `App.vue` 里有个 reset |
| **无设计令牌** | 颜色**硬编码**在各文件里，品牌色 `#d97757` 重复 **48 处** |
| **空目录** | `components/base/`、`components/features/` 是脚手架，**完全是空的** |
| **样式方式** | 14 个文件各写 `<style scoped>` |

---

## 三、技术方案

| 决策 | 做法 | 理由 |
|---|---|---|
| **要不要引 UI 库** | **不引**。手写 + 系统化 | 引库要重写所有已有页面的样式，返工大；且破坏现有视觉一致性 |
| **设计令牌** | `src/styles/tokens.css` 定义 CSS 变量：颜色 / 间距 / 圆角 / 阴影 / 字号 | 一处改，处处生效 |
| **基础样式** | `src/styles/base.css`：reset、排版、滚动条 | 取代现在散落的全局样式 |
| **基础组件** | 填充 `components/base/`：Button / Card / Modal / Input / Table / Tag / Badge / Toast / Skeleton / EmptyState / Loading | 新页面直接用，老页面逐步替换 |
| **暗色模式** | **不做**（超出范围） | |
| **响应式** | 只保证 **1366×768 以上**正常 | 演示场景是笔记本 / 台式机 |

### ⚠️ 时机策略（重要，决定会不会返工）

> **令牌和基础组件在 P0 就建立**，之后 P1–P4 的新页面**天生就用它们**；P5 只做**老页面回填**。

如果等到 P5 才建令牌，前面 P1–P4 写的新页面（M1 演示页、M2 讨论区、M4 聊天页、M6 五个管理页……）全都得返工重写样式。

**这条策略的价值就是把"返工"变成"默认"** —— 新页面写的时候就是规范的，最后只需要回头收拾老页面。

## 四、开发步骤

| # | 步骤 | 时机 | 验收 |
|---|---|---|---|
| M7-1 | `tokens.css` + `base.css` | **P0** | 页面外观不变，但颜色改一处能全局生效 |
| M7-2 | `components/base/` 基础组件 | **P0** | 组件在测试页可渲染 |
| M7-3 | 新页面一律用令牌 | **P1–P4** | 新页面无硬编码颜色 |
| M7-4 | 老页面回填 | **P5** | 全站视觉统一 |
| M7-5 | 全局样式检查 | P5 | 搜索确认无残留硬编码色值 |

## 五、验收标准

- [ ] 全站颜色来自令牌，`grep` **搜不到硬编码** `#d97757`
- [ ] 登录 / 首页 / 课件 / 课堂 / 记录 / 管理端 **视觉风格统一**
- [ ] 无布局错位、无文字溢出
- [ ] 新页面（M1–M6 产生的）**天生就是规范样式**，无需 P5 返工

## 七、明确不做

| 不做 | 原因 |
|---|---|
| 引入 UI 组件库 | 返工大，破坏现有视觉一致性 |
| 暗色模式 | 超出范围 |
| 移动端适配 | 演示场景是桌面浏览器 |
| 动画 / 过渡特效 | 非必要，优先保证功能 |
