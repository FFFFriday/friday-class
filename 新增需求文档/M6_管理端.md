## 一、功能描述

管理员（**新角色**）可管理**用户 / 课堂 / 课件与存储**三大块，含"随时暂停所有课堂"。

### 先回应 Friday 的疑问

> Friday 原话：「管理端，只需要做各种 crud 不就行了吗？你创建一个账号，给一个标签，不就完成了吗？为什么有这么多问题？」

**概念完全正确，它就是 CRUD，没有任何技术难点。**本册列这么多条，是因为**接口和页面数量多**，不是因为难。

唯一需要专门注意的只有一件事：**别忘了给 `/api/admin/**` 配 `hasRole('ADMIN')` 这一行**。
漏配的后果不是"功能不好用"，而是**任何登录学生都能删库、能重置任何人密码**。

所以本册把这一行单独拎出来，并配一条硬性验收。

## 三、技术方案

| 关注点 | 做法 |
|---|---|
| **权限（最关键）** | `SecurityConfig` 增加 `requestMatchers("/api/admin/**").hasRole("ADMIN")`，**放在白名单之后、默认 deny 之前**。**必须配套写验证脚本**证明学生调不通 |
| **角色** | `Role` 枚举加 `ADMIN`；管理员账号 **SQL 预置**（沿用"注册只建学生"的既有策略） |
| **强制下课** | 复用 `ClassSessionService` 的下课逻辑，额外写 `ended_by` / `end_reason`，并广播 `ended` |
| **暂停语义** | 见下方 ⚠️ |
| **踢人** | 服务端关闭该用户的 WS 连接 + 广播 `kicked{reason}` + 写 `session_participant.left_at` |
| **批量操作** | `pause-all` 等 = 查所有 `status='LIVE'` 的课堂 → 逐个执行 → **汇总返回成功/失败数**（**不要因为一个失败全回滚**） |
| **存储删除** | 封装 `CoursewareDeleteService`：DB（级联）+ `storage/coursewares/` + `storage/slides/{id}/` **三处一起清**，漏一处就是磁盘垃圾 |
| **孤立文件清理** | **必须先列后删**：`GET /orphans` 只返回列表，人工确认后把要删的 path 传回 `clean`。**绝不做全自动删除** —— 误删不可逆 |
| **审计** | 每个写操作后插一条 `admin_audit_log`。用 `AdminAuditService.record(...)` 收口一处 |

### ⚠️ 「暂停」的语义必须说清（重要）

媒体流是**点对点直连**的，服务端**管不到画面**。管理员点「暂停所有课堂」的实际效果是：

| 会发生的 | 不会发生的 |
|---|---|
| 课堂状态改为 `PAUSED` | ❌ 老师的画面**不会**被服务端切掉 |
| 广播 `class.paused`，学生端盖遮罩"课堂已被暂停" | ❌ 声音不会停 |
| 讨论区、AI 提问被禁用 | |
| 老师端收到提示，可自行停止共享 | |

> **要真正停画面，必须老师端配合**（收到 `class.paused` 后停止共享轨道）。
> 这是 P2P 架构的固有边界，**不是缺陷** —— 文档和界面都要写明，避免"点了暂停画面还在"被当成 bug。

## 六、验收标准

- [ ] **学生 token 访问任何 `/api/admin/**` 返回 403**（安全验证，**必做，第一优先级**）
- [ ] 管理端能建教师账号并能登录
- [ ] 点「暂停所有课堂」→ 所有进行中课堂变 PAUSED，学生端出现遮罩
- [ ] 强制下课 → 该课堂学生端**立即**跳到"已下课"
- [ ] 踢人 → 被踢的学生端断开并有提示
- [ ] 删除课件后，磁盘上**源文件和幻灯片目录都已清空**
- [ ] 孤立文件清理**必须经过确认步骤**才删
- [ ] 每次管理操作在审计日志里**有记录**
- [ ] 批量操作部分失败时，返回成功/失败计数，不整体回滚
