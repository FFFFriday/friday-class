## 一、功能描述

课堂内的**纯文字**讨论区。所有在场学生和老师都能发言，老师可以删除不当发言。

**它同时是 M5 的数据源**：课堂记录要展示发言时间线，课堂总结要基于发言内容。

---

## 二、接口设计

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/chat/{sessionId}/messages` | 需登录 | 拉历史。参数 `afterId`（增量）或 `beforeId` + `limit`（翻页） |
| DELETE | `/api/chat/messages/{id}` | **教师 / 管理员** | 软删除该条发言 |

**发送不走 REST，走 WebSocket `chat.send`**（低延迟）；REST 只负责"拉历史"和"删除"。

> 为什么这么分？—— 沿用项目既有取舍：**状态类、不能丢的走 POST/GET；高频、可容忍丢失的走 WS**。
> 聊天丢一条无所谓，翻页不能丢（详见 `02_技术约定` §1.1）。

### 请求 / 响应示例

```jsonc
// GET /api/chat/{sessionId}/messages?afterId=120&limit=50
{ "code": 0, "message": "ok",
  "data": {
    "items": [
      { "id": 121, "userId": 7, "nickname": "演示同学", "role": "STUDENT",
        "content": "老师这里没听懂", "pageId": 88,
        "createdAt": "2026-09-20T22:05:11" }
    ],
    "hasMore": false
  } }

// DELETE /api/chat/messages/{id} 响应
{ "code": 0, "message": "ok", "data": null }
```

**错误**：`403`（非本课堂教师）、`BIZ_RATE_LIMITED`（发言过快）

## 三、技术方案

| 关注点 | 做法 |
|---|---|
| **传输** | 上行 `chat.send{content, clientMsgId}`；服务端落库后广播 `chat.new` 给全课堂 |
| **防重复** | `clientMsgId`（前端生成的 UUID）做**短时（60 秒）去重**，防止网络重发导致重复发言 |
| **限流** | **每人 1 条 / 2 秒**（沿用现有 `QaService` 的进程内限流写法）。超限回 `BIZ_RATE_LIMITED` |
| **XSS 防护** | 内容**纯文本存储**，前端**纯文本插值渲染**（`{{ }}`），**严禁 `v-html`** —— 项目既有铁律 |
| **长度** | 单条 ≤ 1000 字符（与表结构一致），超长截断并提示 |
| **删除** | 软删除 + 广播 `chat.deleted`，所有客户端把它置灰为「该发言已被老师撤回」 |
| **页码标记** | 发言时前端带上当前 `pageId`，服务端落库。让课堂记录能显示"这条是在第 N 页说的" |
| **内容过滤** | **不做**关键词过滤（超出范围）。只做长度与频率限制 |
| **历史加载** | 进入课堂时用 `afterId=0` 拉最近 N 条；之后用 WS 增量追加，**不轮询** |

### 关于 XSS 的硬性要求

**这是本项目唯一一处"必须专门验证"的安全点。**

- 后端：`content` 原样存 TEXT，**不做 HTML 转义**（转义是渲染层的事）
- 前端：**只能**用 `{{ message.content }}` 插值。**代码评审时重点检查有没有人图省事写成 `v-html`**
- 验收：发一条 `<script>alert(1)</script>`，页面上必须**原样显示为文字**

## 四、前端改动

| 文件 | 动作 | 说明 |
|---|---|---|
| `components/features/ClassChatPanel.vue` | **新建** | 讨论区面板：消息列表 + 输入框 + 发送。老师视角多一个"删除"按钮 |
| `pages/LivePage.vue` / `pages/TeacherLivePage.vue` | 更新 | 挂载讨论区面板（**可折叠侧栏，别挤占视频区**） |
| `composables/useClassChat.js` | **新建** | 消息列表状态、增量拉取、发送、去重 |

### UI 布局要点

学生端右侧要从"只有一个 AI 面板"变成"**讨论区 + 知识点 + AI 问答**"三块。建议做成**标签页切换**，不要三个面板堆叠——否则视频区被压得很小。

## 五、开发步骤

| # | 步骤 | 验收 |
|---|---|---|
| M2-1 | `chat_message` 表 + 实体 + 仓库 | 能插入 / 查询 |
| M2-2 | WS `chat.send` / `chat.new` 打通 | 两个标签页能互见发言 |
| M2-3 | 拉历史接口 + 进入课堂自动加载 | 刷新后能看到之前的发言 |
| M2-4 | 限流 + `clientMsgId` 去重 | 连点发送只出现一条 |
| M2-5 | 老师删言 + 广播 | 删除后双方都变"已撤回" |
| M2-6 | 讨论区面板 UI | 折叠不挡视频；长消息不撑破布局 |

---

## 六、验收标准

- [ ] 学生发言，老师端和其他学生端 **2 秒内**看到
- [ ] 刷新页面后历史发言还在
- [ ] 连点发送按钮，**只产生一条**发言
- [ ] 老师删除后，学生端显示"该发言已被老师撤回"
- [ ] 发言内容含 `<script>alert(1)</script>` 时，**原样显示为文字，不执行**（安全验证必做）
- [ ] 发言过快时给出"慢一点"的友好提示，而不是红色报错
